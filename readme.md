# KoishiPlugin-QQMudae

一个基于 **Koishi** 的群聊角色收集 / 抽卡插件。

本项目最初参考了 AstrBot 版本的 Mudae 风格角色收集玩法，并重新使用 TypeScript 与 Koishi 数据库体系实现。当前版本已经不再采用“每天只能成功抽卡一次”的机制，而是改为 **金币经济系统**：

- 每日签到获得金币
- 花费金币抽卡
- 图鉴中的角色可以出售换取金币
- 角色人气计入群排行
- 同一群内，同一个角色同时只能属于一名玩家

> 当前版本仍处于开发阶段，功能与数据库结构可能继续调整。

---

## 功能

### 🎴 抽卡

使用：

```text
/抽卡
```


每次抽卡消耗固定金币。

当前逻辑会在代码层面自动排除：

- 自己已经拥有的角色
- 当前群其他成员已经拥有的角色

因此正常情况下，不会出现“抽到重复角色后需要重新发送一次抽卡”的情况。

角色成功获得后会自动加入图鉴，并增加玩家的总人气。

---

### 💰 每日签到

使用：

```text
/签到
```

每天可以领取一次金币。

当前默认：

```text
每日签到：100 金币
单次抽卡：100 金币
```

也就是说，每天签到得到的金币基本等于一次免费抽卡机会。

---

### 📖 图鉴

使用：

```text
/图鉴
```

分页：

```text
/图鉴 2
```



图鉴会显示：

- 当前金币余额
- 图鉴总人气
- 当前群排名
- 已收录角色数量
- 角色名称
- 角色 ID
- 角色人气
- 当前出售价值

私聊中不会显示群排名。

---

### ♻️ 出售角色

使用：

```text
/出售 <角色ID>
```

例如：

```text
/出售 10452
```

出售后：

- 角色从自己的图鉴中移除
- 玩家总人气下降
- 获得金币
- 该角色重新回到当前群的可抽取卡池

出售价格会根据角色 `heat` 计算，但会限制在低于一次完整抽卡的范围内，避免出现无限“抽卡 → 出售 → 抽卡”的正收益循环。


---

### 🏆 群排行

使用：

```text
/排行
```

或：

```text
/群排行
```

显示当前群图鉴总人气 Top 10。

相同总人气采用并列排名，例如：

```text
1. Alice
1. Bob
3. Carol
```

---

### 🔄 终极轮回

> 需要较高权限。

使用：

```text
/终极轮回
```

会先提示确认。

真正执行：

```text
/终极轮回 确认
```

将清空当前群的：

- 玩家图鉴
- 角色归属
- 金币
- 总人气
- 排行
- 签到记录

只影响当前群，不影响其他群的数据。

---

## 当前经济参数

默认参数定义在 `src/index.ts`：

```ts
const DRAW_COST = 100
const DAILY_REWARD = 100
```

出售价格会根据角色人气计算，并限制最低与最高值。

如果需要调整经济节奏，可以直接修改这些常量。

## 角色数据

角色数据位于：

```text
src/data/characters.json
```

当前角色结构大致如下：

```json
{
  "id": 12393,
  "name": "牧濑红莉栖",
  "alias": "牧瀬紅莉栖",
  "heat": 4176,
  "gender": "女",
  "image": [
    "https://example.com/image.jpg"
  ]
}
```

主要字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 角色唯一 ID |
| `name` | 显示名称 |
| `alias` | 别名 / 原名 |
| `heat` | 角色人气 |
| `gender` | 性别信息 |
| `image` | 角色图片 URL 列表 |

当前角色库约包含一万五千余名角色。

插件启动时会通过 `CharacterManager` 加载整个角色库。

## 安装与开发

本项目基于 Koishi 模板仓库开发。

在 Koishi 项目根目录安装依赖：

```bash
npm install
```

启动开发环境：

```bash
npm run dev
```

然后在 Koishi 控制台中启用：

```text
qq-mudae
```

即可开始测试。

## 常用指令

| 指令 | 说明 |
| --- | --- |
| `签到` | 每日领取金币 |
| `抽卡` | 花费金币抽取角色 |
| `图鉴 [页码]` | 查看自己的角色 |
| `出售 <角色ID>` | 出售自己拥有的角色 |
| `排行` | 查看当前群人气排行 |
| `群排行` | `排行` 的别名 |
| `终极轮回 确认` | 清空当前群全部游戏数据 |

## 数据隔离

角色归属和玩家数据都会按照：

```text
platform + guildId
```

进行隔离。

因此：

- 不同群之间的角色归属互不影响
- 同一个角色可以在不同群分别被不同玩家拥有
- 私聊不会参与群排行

---

## 数据库

插件目前主要使用两张表。

### `mudae_player`

保存玩家状态，例如：

```text
platform
guildId
userId
username
totalHeat
coins
lastDailyDate
```

### `mudae_claim`

保存角色归属：

```text
platform
guildId
characterId
userId
claimedAt
```
